# Завершення зрізу

Канонічний текст команди. Claude Code викликає його через `/slice-finish`,
Codex — через скіл `slice-finish` (`.agents/skills/slice-finish/`).

Правила — `RulesForAIVibeCoding.md`, розділи *Work cycle*, *Traceability*,
*Surgical changes*. Тут — порядок дій на фініші сесії.

Задача релізу (`**Тип:** release`) цією командою не закривається: у неї два
коміти, до деплою і після, і порядок задає розділ *Environments*, підрозділ
*Releases and deployment*. Скажи це й зупинись.

## Виконай по кроках

1. Прогони команду локальної перевірки з `docs/ARCHITECTURE.md`, розділ
   *Project Structure*. **Покажи реальний вивід**, а не висновок про нього.
   «Здається, зелено» не рахується.
2. Онови в `docs/BACKLOG.md` поле `**Статус:**` зрізу (`DONE`, або `BLOCKED`
   з причиною) і додай рядок у Progress Log із тим самим статусом.
   У колонці «Коміт» — тема коміту, який ти зараз запропонуєш, не хеш:
   хеша ще не існує. Якщо статус зрізу продубльовано в Coverage Map — онови
   обидва місця.

   Це єдине, що ти правиш **у `BACKLOG.md`** без окремого підтвердження. Межі
   для решти документів — правила, розділ *Changing docs/*; зокрема запис у
   `docs/OPEN-QUESTIONS.md` при блокуванні правила від тебе вимагають, і він
   теж не потребує окремого дозволу.
3. Прогони `python3 scripts/check-slice.py <SLICE-ID>` і покажи реальний
   вивід. Це механічна частина Definition of Done — не переказуй її,
   не «проходь подумки».

   На Windows у Git Bash `python3` часто відсутній — тоді `python`. Якщо не
   працює жодне, зупинись і скажи мені: див. розділ *Windows* у `README.md`.

   Перевірка шукає ID вимоги **в назві тестового файла або тесту**, і лише у
   файлах, які є тестами (`test_*`, `*_test.*`, `*.spec.*`, `*.feature`, усе під
   `test/`, `tests/`, `spec/`, `__tests__/`). Приймається `FR-014`, `FR_014`, `FR014` у будь-якому регістрі —
   тобто `test_fr_014_filter` годиться так само, як `test_FR_014_filter`.
   ID у коментарі чи docstring **не зараховується**: правило вимагає його саме
   в назві.
4. По неперевірюваній частині DoD (вивід локальної перевірки, мій перегляд
   diff, відсутність зайвої функціональності) — скажи прямо, що з цього
   виконано, а що ні.
5. Покажи diff summary: які файли змінені, що саме, які `FR-*` закриті —
   кожен з коротким описом у дужках, не голим ID (правила, розділ
   *Asking questions*). Кожен змінений рядок має простежуватися до мого запиту.
6. Запропонуй повідомлення коміту: `<type>: FR-0XX <опис>`.
   Тип із дозволеного списку, ID у **першому рядку**, рівно три цифри.
7. **Зупинись і чекай на моє «ОК». Не комітай сам.**
8. Після мого ОК — один коміт, код і документація разом. Не два.
9. Наприкінці скажи: що зроблено, що лишилося, які питання відкрилися.

## Якщо `check-slice.py` не проходить

Не обходь його і не правь скрипт — він у списку захищених файлів, і будь-яка
його зміна ламає перевірку цілісності. Назви, який саме пункт не пройшов,
і або доробляй, або повертай зріз у `TODO`.

## Якщо зріз не завершено

Не роби вигляд, що завершено. Правила, розділ *Work cycle*, підрозділ
«If the slice could not be finished»: скажи де зупинився, поверни статус
у `TODO` або `BLOCKED` з причиною, незавершений код — у гілку
`wip/<fr-id>-<slice>` або взагалі без коміту, причину блокування —
в `docs/OPEN-QUESTIONS.md`.
